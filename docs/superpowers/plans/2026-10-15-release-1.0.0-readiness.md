# 1.0.0 Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four council-identified release blockers and two accepted extra items so the `strix-battery` tree can be tagged 1.0.0.

**Architecture:** No new modules and no new dependencies. The work is: bring CI up to the four-gate contract `AGENTS.md` already declares, stop a desktop-notification failure from masquerading as a device failure, make the noise-reduction state write atomic, survive a missing `HOME`, isolate four tests from an ambient `STRIX_BATTERY_CURVE`, document the exit-code/JSON contract, and bump the version.

**Tech Stack:** Python 3.12, `unittest` + `unittest.mock`, `ruff`, `ty`, GitHub Actions, `uv`.

**Spec:** This plan implements the 1.0.0 go/no-go decisions from the nine-reviewer council run on `e313987` (`origin/main`). Source of truth for behavior is `AGENTS.md` plus the existing plans under `docs/superpowers/plans/`; this plan does not restate them.

## Global Constraints

- Python `>=3.12`; Linux only (hidraw ioctls).
- Runtime deps stay exactly `pillow`, `pyqt6`. No new third-party dependencies.
- `StrixDevice` methods return `bool` for success and leave `last_status` / `last_error` semantics untouched (`AGENTS.md`).
- Tests: `unittest` + `unittest.mock`, extended in `tests/test_main.py`, never rewritten.
- Every change ends green on all four gates:
  `uv run python -m unittest discover -s tests`,
  `uv run --group dev ruff check .`,
  `uv run --group dev ruff format --check .`,
  `uv run --group dev ty check`.
- Semver pre-1.0 → 1.0.0 is a major bump; the bump lives only in `pyproject.toml` and `uv.lock` refreshes in the same change.
- `notify()` runs on the Qt GUI thread and must never stall or raise.
- Docs under `docs/` are excluded from Ruff; plans are not shipped code.

## Review Focus

- **A `notify-send` failure that is not `FileNotFoundError`/`TimeoutExpired`** — the user must still see the real battery reading, and `set_sleep`/`set_noise_reduction` must still report success when the HID write succeeded. (Task 3.)
- **Two processes writing the noise state file at once** — the loader must never read torn JSON that reports a stale `off` as authoritative. (Task 4.)
- **A process with no `HOME`** (service/cron/systemd) — construction and every query must still work. (Task 5.)
- **A developer who exported `STRIX_BATTERY_CURVE`** — the suite must pass without needing to unset it. (Task 6.)
- **A panel script reading `--json`** — the exit-code and JSON shape must be discoverable from the README, not only from tests. (Task 7.)

### Task 3: A notification failure must not report the device as offline

**Files:**
- Modify: `strix_battery/device.py:372`

**Interfaces:**
- Consumes: `NotifyTests` harness in `tests/test_main.py`, the `asus_ioctl()` helper (`:306`).
- Produces: `notify()` that suppresses every `OSError`, so `query()`/`set_sleep()`/`set_noise_reduction()` cannot treat a notification failure as a device failure.

- [ ] **Step 1: Write the failing tests**

Add to `NotifyTests` in `tests/test_main.py`:

```python
    def test_notify_swallows_a_bare_oserror(self):
        # EACCES on a non-executable wrapper, EAGAIN when fork hits
        # RLIMIT_NPROC: notify-send can fail with a plain OSError that is
        # neither FileNotFoundError nor a SubprocessError.
        device = StrixDevice()
        with patch(
            "strix_battery.device.subprocess.run",
            side_effect=PermissionError(13, "Permission denied"),
        ):
            device.notify("ROG Strix Go 2.4", "Battery critically low: 12%!")

    def test_a_notification_oserror_does_not_escape_query(self):
        # 3427 mV -> 14%, low enough that query() reaches the notify path.
        def _low_battery_ioctl(fd, request, buf, *args, **kwargs):
            if request == HIDIOCGRAWINFO:
                buf[:8] = ASUS_DEVINFO
            elif request == HIDIOCGFEATURE_64:
                buf[1] = 0x1B
                buf[11] = 0x63
                buf[12] = 0x0D

        device = StrixDevice()
        with (
            patch("strix_battery.device.glob.glob", return_value=["/dev/hidraw0"]),
            patch("strix_battery.device.os.open", return_value=7),
            patch("strix_battery.device.fcntl.ioctl", side_effect=_low_battery_ioctl),
            patch("strix_battery.device.time.sleep"),
            patch("strix_battery.device.os.close"),
            patch(
                "strix_battery.device.subprocess.run",
                side_effect=PermissionError(13, "Permission denied"),
            ),
        ):
            self.assertIsNotNone(device.query())

    def test_a_notification_oserror_does_not_flip_set_sleep_to_false(self):
        def _ioctl(fd, request, buf, *args, **kwargs):
            if request == HIDIOCGRAWINFO:
                buf[:8] = ASUS_DEVINFO
            elif request == HIDIOCGFEATURE_64:
                buf[1] = 0x1B

        device = StrixDevice()
        with (
            patch("strix_battery.device.glob.glob", return_value=["/dev/hidraw0"]),
            patch("strix_battery.device.os.open", return_value=7),
            patch("strix_battery.device.fcntl.ioctl", side_effect=_ioctl),
            patch("strix_battery.device.time.sleep"),
            patch("strix_battery.device.os.close"),
            patch(
                "strix_battery.device.subprocess.run",
                side_effect=PermissionError(13, "Permission denied"),
            ),
        ):
            self.assertTrue(device.set_sleep(30))
```

### Exit codes and JSON

`strix-battery` uses the same exit codes in text and `--json` mode:

| Code | Meaning |
| ---- | ------- |
| 0    | Reported successfully |
| 1    | Headset offline / out of range |
| 2    | Bad usage (e.g. a `--set-sleep` value out of range) |

{"status": "online", "percentage": 71, "voltage": 3904, "charging": false, "sleep_min": 0, "text": "%71"}

```json

```
```
